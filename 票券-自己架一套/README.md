# 票券 — 詳細說明

照著「安裝說明.pptx」一步一步做就能架好（v98 起只要 3 大步）；這份是更完整的說明、用法和進階設定。

一個可以加到 iPhone / Android 主畫面的票券小程式。截圖丟進去會自動讀出商家、券名、到期日和序號，
列表依到期日排序，也能勾幾張產生分享連結給別人，對方用掉之後這邊會同步標記成已使用。

資料全部在你自己的 Google 帳號裡：票券欄位存在一份 Google 試算表，截圖存在雲端硬碟的一個資料夾。
沒有第三方伺服器。

## 這包檔案

| 檔案 | 放哪裡 | 做什麼 |
|---|---|---|
| `安裝說明.pptx` | — | 一步一步的安裝說明 |
| `Code.gs` | Google Apps Script 專案 | 後端。存取試算表和雲端硬碟、呼叫 Gemini 辨識、產生分享頁、發通知 |
| `web` 資料夾 | Cloudflare Pages | 前端 App 本體。整個資料夾一起上傳 |
| `web/brands` 資料夾 | 同上（在 web 裡面） | 店家小圖示（logo 圖檔）。商標屬各家所有，僅供自用；不想用就刪掉，會自動退回字章 |
| `web/_worker.js`、`web/404.html` | 同上 | 讓分享連結變短、朋友打開不會碰到 Google 的錯誤頁。後端網址由網站產生器填好（或設 Cloudflare 的 `EXEC_URL`） |
| `web/kitgen.js` | 同上 | App 的「只下載網站（已經填好你的後端網址）」用的，在你的瀏覽器裡把新版網站填好再給你下載 |

## 第一步：後端（Google Apps Script）

1. 開 <https://script.google.com> →「新專案」，點上方「無標題的專案」改名「票券後端」。
2. 把 `Code.gs` 的內容整份貼進去，取代原本的 `myFunction`，按儲存（磁碟片圖示）。
   時區不用改：程式固定用台北時間（要用別的時區，在「專案設定 → 指令碼屬性」加 `TIMEZONE`，例如 `Asia/Tokyo`）。
3. 上方函式選單選 `setup`，按「執行」。第一次會跳授權：選你的帳號 →「進階」→「前往 票券後端（不安全）」→ 允許。
   （這是你自己的程式，Google 對沒送審的個人專案都會這樣問。）
4. 看下方「執行紀錄」：會印出試算表、截圖資料夾，以及 **OWNER_KEY** —— 抄下來。
5. 右上「部署」→「新增部署作業」→ 齒輪選「網頁應用程式」：
   - **執行身分：我**
   - **誰可以存取：所有人**　← 一定要這個。分享連結是要給沒有 Google 帳號的人點開的。
   - 英文介面：Execute as → Me，Who has access → Anyone
6. 按「部署」，抄下「網頁應用程式」網址（`…/exec` 結尾）。

> **「所有人」會不會不安全？**
> 會拿到的只有知道這串網址的人，而且所有票券操作都要帶 OWNER_KEY 才會過。
> 分享連結是另一套隨機 token，只能看到你指定的那幾張、只能按「我用掉了」，看不到其他票券。
> 如果哪天覺得網址外流了，把指令碼屬性的 `OWNER_KEY` 改掉即可。

## 第二步：網站（Cloudflare Pages）

1. 打開**網站產生器** <https://tickets-37z.pages.dev/kit.html>，貼上第一步的 `/exec` 網址 →「下載你的網站」。
   解壓縮會得到一個 `web` 資料夾，裡面已經填好你的後端網址。（網址只在你的瀏覽器裡處理，不會傳到任何地方。）
2. 登入 <https://dash.cloudflare.com>（沒有帳號就免費註冊）→ 左邊「**Workers 和 Pages**」→「**建立應用程式**」→ 選 Pages、用直接上傳（拖放檔案）。
3. 專案名稱取英文小寫（例如 `my-tickets`），把整個 `web` 資料夾拖進去 → 部署。
   完成後網址是 `https://my-tickets.pages.dev`。
   英文介面：Workers & Pages → Create application → Pages → Upload assets → Deploy site。

不用設 `EXEC_URL`、不用重新部署第二次；分享連結的短網址（`SHORT_BASE`）App 第一次打開時會自己設好。

（不想用網站產生器也可以：上傳這包裡的 `web` 資料夾，再到專案「設定 → 變數與機密 → ＋ 新增」，變數名稱 `EXEC_URL`、值是你的 `/exec` 網址 →「儲存」，
然後右上角「建立部署」把 `web` 資料夾再拖一次。英文介面：Settings → Variables and Secrets → Add → Save；Create deployment。）

也可以放 GitHub Pages 之類的靜態空間，但那裡跑不了 `_worker.js`：分享連結會是 Google 的長網址，
朋友的瀏覽器如果同時登入好幾個 Google 帳號，可能會看到 Google 的錯誤頁。

## 第三步：打開你的網址

1. 電腦瀏覽器打開你的網址。最上面會寫「網站已經接好你的後端，只差貼上存取碼」→ 按「**貼上存取碼**」→ 貼 OWNER_KEY →「儲存」。
2. App 接著請你貼**辨識金鑰**（設定 → 右上角鈴鐺 →「辨識金鑰」）：
   - Gemini 有免費額度，個人用夠用：到 <https://aistudio.google.com/apikey>（用同一個 Google 帳號）按「建立 API 金鑰」（Create API key），複製 `AIza` 開頭那串貼上 →「儲存金鑰」。
   - 想用 Claude 也可以（付費，約每張截圖 NT$0.1，比較準）：在同一格選「Claude」貼上 `sk-ant-` 開頭的金鑰。
3. 電腦上會出現「換到另一台裝置」的 QR，用手機掃一下，手機就設定好了。
4. 加到主畫面：
   - **iPhone**：Safari 下方分享鈕 →「加入主畫面」（要用 Safari，Chrome 不行）
   - **Android**：Chrome 右上選單 →「安裝應用程式」

不用再進 Apps Script 的「指令碼屬性」新增 `GEMINI_KEY`、`SHORT_BASE`（v98 起都在 App 裡完成；Discord 通知、自動匯入這些選用功能還是在指令碼屬性設）。

## 之後怎麼更新

有新版本時，App 最上面會出現「有新版本 vXX」，點「看看改了什麼」會列出每一版改了什麼和步驟
（App 大約每 6 小時看一次；也可以到「設定 → 更新 → 詳細資訊」按「檢查有沒有新版本」）。這一版不想要就按「這版先不要」。

更新在電腦上做：

1. **後端**（版本說明寫「後端也有改」的時候）：打開「票券後端」，把 `Code.gs` 整份換成新的 → 儲存 →
   「部署 → 管理部署作業 → 鉛筆 → 版本選『新版本』→ 部署」。網址不會變，手機不用重新設定。**不要按「新增部署作業」**（會換網址）。
2. **網站**：App 的「更新」頁按「**只下載網站（已經填好你的後端網址）**」，解壓縮後到 Cloudflare 你的專案 →
   右上角藍色「**建立部署**」→ 把 `web` 資料夾整個拖進去 → 部署。
   （舊版 App 沒有這顆按鈕的話，用網站產生器 <https://tickets-37z.pages.dev/kit.html> 下載也一樣。）

做完回 App「設定」最下面按「強制更新」。只做了一邊的話，App 會提醒還差哪一邊。
你的票券和設定都在你自己的試算表和指令碼屬性裡，更新不會動到。

## 用法

**匯入截圖**　下方「拍照或匯入」→ 從相簿一次複選多張。v98 起**先上傳、背景辨識**：每張縮好就傳（一次兩張，幾秒就傳完），傳完匯入頁自己關掉，可以去做別的事、App 關掉也沒關係，辨識在後端排隊慢慢跑。
列表最上面會寫「辨識中：還有 N 張…」，好了變成「N 張辨識好了，確認後存入」（App 沒開的話 Discord 也會說一聲）；點進去就是確認頁：每張都能確認／修改 → 底下的按鈕依勾了幾張寫字（只存一張寫「存入這張票券」，全部勾了寫「全部存入（3 張）」，只勾一部分寫「存入勾選的 2 張」；v89）。
沒勾的那幾張截圖會丟進雲端硬碟的垃圾桶（還原得回來）。設定 →「匯入與整理」→「辨識好、等你確認」也進得去。
辨識有把握的會標綠色，沒把握的標紅色提醒你檢查到期日。看起來匯過的會標黃色並預設不勾。

辨識失敗的會自己再試（一張最多三次），三次都不行就在確認頁最下面列出原因，可以「再辨識一次」或「不要了」。
Gemini 每分鐘次數到頂或太忙時，後端會自己等幾秒重試；今天的額度用完了就 15 分鐘後再接著辨識。
上傳的時候手機不會自動關螢幕；傳完就沒有這個限制了。後端還是 v97 以前的話，照舊一張一張辨識（要停在匯入頁等）。

按下存入之後 Discord 會收到一則「票券匯入（App）」：新增了哪幾張和到期日（最下面的 ＋ 自己填的會註明「手動新增」）、哪幾張沒存（看起來匯過、沒勾）、哪幾張辨識失敗，跟上傳區自動匯入的通知同一個格式。不想收就把 `Code.gs` 裡的 `NOTIFY_APP_IMPORT` 改成 `false`。

**從相簿直接分享進來（Android）**　在相簿或任何 App 看到票券截圖，按「分享」，選單裡會出現「票券」，
一按就直接進匯入流程，可以一次選多張。iPhone 沒有這個選項，照舊用 App 裡的匯入。
分享過來的若是連結或文字（例如從 LINE 禮物頁按分享），會自動開一張手動票券並把內容放進備註，
並提醒你先截圖再從相簿分享才有條碼。
這靠 `manifest.webmanifest` 的 `share_target` 和 `sw.js` 裡收圖那段，兩個檔都要是新版。

**沒有截圖的券**　最下面的 ＋ 自己填。

**不怕票券變多**　依日期看時，一組超過 12 張就先收起來；依商家看時，每一家先露 2 個（精簡列表一疊算一個，完整排版一張算一個），點一下再露到 6 個，再點全部，再點收回去（v91）；標題右邊的數字跟著寫「2/9 種 ˅」→「6/9 種 ˅」→「9 種 ˄」（完整排版寫「2/20 張」），已露出來的卡片底下有一條薄薄的箭頭「﹀ 還有 7 種」，明說這家還有別的；點標題的數字或點箭頭條都一樣。點箭頭條時畫面會跟著捲，箭頭條停在手指底下，新露出來的從上方淡入，所以同一個地方連點就是 6 種 → 全部 → 收起（v92）。v93 起數字跟在店名後面（「麥當勞 2/9 種 ˅」），整條標題都能點。

**右邊的店家卷軸**　依商家看「全部」時（三家以上），畫面右邊有一排店家圖示，順序跟列表一樣。紫色框住的是畫面上看得到的那幾家，滑過去的會變淡，框下面的就是還沒看到的。點圖示，或按住卷軸上下拖，直接跳到那一家，左邊會冒出店名（v93）。依日期看、只選幾家、多選時不會出現。種類不到 7 個的店，第 2 段就是全部（只有兩段）；2 種以下的店沒有切換（v89 起以前是底下一整條「還有 N 張」）。
精簡列表（預設）會把同一家、券名一樣的券（例如好幾張大薯）併成一疊：第一張右上角寫「×6」，點它展開看每一張，點票券本身照常開詳情；已使用、已過期、分享出去的、餘額型不併，多選時會攤開，設定 →「列表」→「完整」就不併。一疊算一種來決定要不要收起來。
分享紀錄也一樣：還在外面的排前面，一次先列 8 筆，
已收回、已過期，還有裡面的票都被用掉（或都過期）的，收進最下面的「已結束的 N 個」裡。

**快速多選**　直接點票券左邊那條色帶就會勾起來，不用先按下面的「選取」（像 Gmail 點頭像那樣）。
勾第一張就自動進入多選，全部取消就自動離開。點卡片中間還是開詳情。
多選時，每張票券左邊的半圓缺口上會出現一個圈，勾起來會變成主色加打勾；點那個圈也能勾、取消。

**結帳時一次用多張（出示模式）**　下方「選取」→ 點要用的幾張 →「出示這 N 張」。
畫面會變成整片白底全螢幕，一張佔一頁，左右滑換下一張。最上面左邊顯示第幾張，右邊兩行寫「上一張：…」「下一張：…」是哪一張（點一下就翻過去），不用點進放大圖就看得到。
每頁底下的「標記已使用」按下去會蓋章並自動翻到下一張，按錯可以馬上復原。點截圖可以再放大，
放大之後最底下有「標記已使用」（用掉之後變「改回未使用」，那顆就是復原；後面還有下一張、會自動翻過去的時候，提示上才多一個「復原」，v89），
兩旁是「上一張／下一張」、上面三行寫「上一張：…」、「2 / 5」和這張的券名、「下一張：…」是哪一張，左右滑也能換，連續掃好幾張不用每張都關掉再點；
在放大畫面標記完會自動換到下一張。關掉放大畫面，會停在剛剛看到的那一張。
單張票券的詳情頁也有「放大出示」。

**檢查重複**　最下面的齒輪 →「檢查重複的票券」。比對序號（去掉符號、不分大小寫，六碼以上才算數），
沒有序號的則比對商家、券名、到期日。每組保留最早匯入的那張，已使用的會排後面免得誤刪，
其他按「刪掉」兩次就會刪掉，截圖進雲端硬碟垃圾桶。

**改名規則（v67）**　最下面的齒輪 →「改名規則」。貼上一批「舊名字 → 新名字」（每行：舊商家、舊券名、新商家、新券名，用 Tab 或逗號隔開，
可以從 Excel 直接複製貼上；舊券名空白＝這家商家的任何券名，例如 7-ELEVEN → 7-11），之後匯入票券時，名字跟舊名字一樣、
或只差空格、括號、商家名、「好禮即享券」這類固定字、一個錯字的，會自動換成新名字（App 匯入和雲端硬碟上傳區匯入都會），
備註寫「已改名（原：…）」，種類維持原樣；App 匯入的確認畫面可以一鍵「改回原名」。規則放在試算表的「NameRules」分頁，也可以直接在那裡改。
沒有任何規則時什麼都不會變；指令碼屬性 `NAME_RULES_OFF` 設成 `1` 可以整個關掉。沒有規則對得上的新名字，只做通用整理：
商家別名統一（規則裡「舊券名空白」的那幾條）、去掉券名裡重複的商家名和「好禮即享券／即享券／兌換券」。

**餘額型票券（v69）**　可以分次使用的券（標題寫「餘額型」「分次使用」「商品卡」的，例如 SOGO 好禮即享券、7-ELEVEN 商品卡）。標成餘額型之後，
按「標記已使用」不會直接進「已使用」，會先跳出來問你還剩多少：填剩下的金額（大於 0）就留在「可用」，票面寫「剩 $700」；
填 0 才算用完、進「已使用」；也可以按「晚點再確認」，這張會標「待確認餘額」，隔天早上的 Discord 提醒會列出來。
確認時可以先存一個「查餘額網址」，下次一鍵打開。
怎麼標：新匯入的券標題寫了「餘額型」「分次使用」「商品卡」會自動標好；已經在的券，上面會跳黃色提示條，或最下面的齒輪 →「餘額型票券」一次勾選
（電子禮券、禮物卡這類只列「疑似」，預設不勾）；也可以在票券的「編輯內容」勾「餘額型」。上面多一格「餘額型」篩選，看的時候會寫已確認的剩餘金額合計。
分享給朋友的餘額型票券，朋友按的是「我用了一些」：不會進「已使用」，你會收到通知，剩多少由你確認。
票券表會自己多出幾欄（kind、balance、balanceUrl、balanceAt、pendingAt、pendingBy），不用自己加；更新後記得把 `Code.gs` 也重新部署。

**餘額型：幫你填「剩多少」（v70）**　三種情況，都是你看過、按了才算數，不會自己亂改：
①票面上明寫著「餘額」「剩餘金額」的（例如 SOGO、商品卡、電子禮券的截圖，常在右上角），匯入時 AI 會一起讀出來，自動標成餘額型、記好剩餘金額；
一定要有那行「餘額：…」的字才收，只寫面額的不會當成餘額。
②已經在的餘額型：最下面的齒輪 →「餘額型票券」最上面會列出「還沒確認過剩多少」的券（沒用過、沒過期、看得出面額的），
沒用過的券餘額就是面額，勾好、按「記成面額」一次記起來；用過的或不確定的取消勾選。
③用過的券：按「標記已使用」跳出的面板有一顆「用截圖讀餘額」，選一張有寫剩餘金額的畫面（右上角常有），AI 讀出來會幫你填好、
並寫出它讀到哪一行，你看對了再按「更新餘額」。截圖上只寫面額、沒印餘額的讀不到，就自己看原本的 App 或網站再填；截圖印的是拍下那一刻的餘額，用過之後要拿新截圖。
這個功能要用 Gemini 或 Claude 辨識（設了 `GEMINI_KEY` 或 `ANTHROPIC_KEY`）；網站和 `Code.gs` 兩邊都要更新。

**用網址查餘額（v71）**　PayEasy 賣的電子禮券（萬家福／樂家康、康達盛通這類，網址長得像 `https://www.payeasy.com.tw/Electronic/coupon?id=…`）不用登入就看得到餘額，App 可以替你查。
設定 →「匯入與整理」→「餘額型的券」最上面：把券網址貼進去（一行一個）按「看看對到哪幾張」，會用序號對到 App 裡的券（序號只差幾位的列成「可能是這張」，要自己勾）；對得到的存下網址、更新餘額，App 裡沒有的可以直接新增（用網站的資料和條碼圖）。
存了網址之後，按「一鍵更新餘額」會把每張重讀一遍：變少或一樣直接記、剩 0 才進「已使用」、變多先問你、序號對不上的不寫。
按「標記已使用」跳出來的面板，存了網址的券多一顆「從網址讀餘額」（只填進欄位，由你按「更新餘額」才存）。
網址等於那張券的存取碼：只存在你的試算表，不進通知和分享頁；後端只會去讀 `www.payeasy.com.tw`。其他商店（SOGO、7-11、全聯）要登入或密碼才看得到餘額的，沒辦法這樣查，照舊用截圖。
這個功能網站和 `Code.gs` 兩邊都要更新。

**只看圖**　票券詳情頁點截圖、圖檔牆點縮圖、重複檢查點縮圖，都會全螢幕只顯示那張圖，

可用／全部兩個頁籤，下面還能切「依匯入時間／依到期日／依使用時間」排序（v94 起預設依匯入時間，新匯入的排最前面），

「複製序號」「編輯內容」「刪除」在最下面（v94；以前三顆按鈕都在最下面，截圖長的要滑到底才看得到）。

電腦上也能用方向鍵，手機可以左右滑。v95 起真的照畫面走：依商家看就一家一家走，同一疊（例如好幾張中薯）連在一起，

**匯入進度**　匯入時的進度條會釘在標題列下面，捲到下面看辨識結果時也看得到現在跑到第幾張。

**單張分享**　點進某張票券，按票卡下面的「分享這張」就能直接產生連結，不用回列表選取。
已經分享出去的票券，詳情頁上方會顯示連結本身，可以直接複製或收回。

**分享**　下方「選取」→ 點選要給的幾張 → 右邊的分享鈕 →「分享這 N 張」→ 選連結的有效期間 → 產生連結 → 複製或用系統分享傳出去。有效期間可以選 3／7／14／30 天、不限，或「跟票券一起到期」（v73：連結在票券到期那天失效；好幾張一起分享時用最晚到期那張；票券沒有到期日就沒有這個選項）。

連同那段話一起送）、「複製連結」、「複製文字＋連結」。那段話是你寫的「給對方的話」，沒寫就是「這 3 張票券給你用」。

真的沒建成的話，原因會直接寫在畫面上，可以再按一次。
對方點開看到截圖和序號，按「我用掉了」之後，你這邊那張就會變成已使用。
用不到的話他可以按「用不到，還給他」（按兩下確認）：那張從他的連結拿掉、回到你的「可用」，
他那邊的條碼會收起來，Discord 會通知你「小明 把 ○○ 還給你了」。已經用掉的不能還。
截圖點一下會全螢幕放大，可以再按「放大」或「轉橫向」，條碼會變粗變長，店員比較好掃。

**分享連結馬上出現（v72）**　按「產生分享連結」，連結馬上就出現，可以先複製、先傳出去；後端在背景存，存好會打勾「✓ 已建立」。網路不穩存不進去，App 會自動用**同一條連結**重試（關掉 App 也沒關係，下次打開會補存），不會再叫你「再按一次」、也就不會同一張分享出兩條。對方剛好在存好之前點開，會看到「還在準備中」，幾秒後自己重新整理。選的票券已經在一條還沒失效的連結裡，分享畫面最上面會先告訴你（哪天、給誰、對方開過沒），可以直接「用原本的連結」，真的要新的才按「改給新的連結」（v75：這幾張會從舊連結收回，同一張不會同時在兩條連結裡）。一打開分享畫面就會先叫醒後端，存的那一下比較快。這台手機第一次分享時，還是要等後端回應一次（之後才知道連結長什麼樣子）。網站和 `Code.gs` 兩邊都要更新。

**親友連結（v75）**　設定 →「分享」→「＋ 新增親友」：寫名字、勾商家（例如星巴克、麥當勞），按「單張」可以一張一張加或拿掉，
然後「建立連結」→「傳給他」。這是給家人、好朋友的**長期連結**，跟一次性的分享連結不一樣：
- 他打開只看得到你挑的商家（以後新匯入的同一家也會自動出現）＋單張加的，而且只有還能用的；分享給別人的、用掉的、過期的都不會出現。
- 截圖和序號要按「出示」才出來；用掉之後按「我用掉了」（按兩下），會自動記是他用的，Discord 照樣通知你；30 分鐘內可以自己復原。餘額型按「我用了一些」，剩多少由你確認。
- 他不能改、不能刪、不能分享，也看不到你的設定和分享紀錄。
- 你的列表上，他看得到的券會標「親友：媽媽」。每個親友可以「改挑選」「打開看看」（不算他打開過）「換新連結」（舊的馬上打不開）「停用」。
- 資料在試算表的「Members」分頁，第一次新增親友時自動建立。網址跟分享連結一樣是 `/s/…`（親友的碼比較長）。
- 兩個親友挑到同一家時會看到同一批券，同時用到同一張的話會撞券（目前沒做「先佔住」）。

**在別人手上的券，出示前先問（v75）**　分享出去、對方還能用的券，你自己在詳情頁、出示模式、放大畫面要看截圖時，
會先蓋著寫「這張在小美手上」，按「還是要出示」才給看（這次打開 App 有效）。兩邊都拿去用會撞券，自己要用最好先收回。

**防重複**　同一張券不會有兩個人同時以為還能用：分享頁上已使用的會直接變灰、按鈕消失。
分享出去的券也會從「可用」和「30 天內到期」裡移出去（標題旁的張數也不算），要看它們按「已分享」（只放朋友手上還能用的，用掉或過期的在「已結束」），
或在設定的分享紀錄裡收回。連結過期或收回之後，那張會自動算回「可用」。

**分享時「我也留著」（v76）**　分享畫面每一張券右邊有一個「我也留著」（選多張時右上角還有「全部我也留著」）。
勾了的，分享出去之後你自己這邊還留在「可用」（列表標「已分享給 小美・我也留著」），出示前不會先問，就是「誰有空誰先用」的意思：
他在分享頁按「我用掉了」，你這邊就變已使用；你先標已使用，他那邊那張就變灰。沒勾的照上面「防重複」的做法。預設都不勾。
這一段網站和 `Code.gs` 都要更新（分享紀錄表會自動多一欄 `keepIds`，不用手動加）。
分享出去之後才想留著也可以（v86）：點那張券進詳情頁，分享那一塊有「我也留著」（再按取消）；同一條連結好幾張時還有「整條都留著」。這一項也要網站和 `Code.gs` 都更新。

**已經用掉的券又匯入（v76）**　匯入時如果這張券的序號跟「已使用」裡的某張一樣，確認畫面會標「這張已經用掉了（日期）」，預設不存；
勾了「存入這一張」才存，而且直接放進「已使用」，不會變成可用。Discord 的匯入通知（App 匯入、上傳區自動匯入）也會多寫一段「已經用掉的券又被匯入」。

**返回鍵（v76）**　Android 右滑或按返回，會先關掉最上面那一層（詳情、設定、分享、出示模式、放大圖…），不會直接關掉 App；
多選（勾了票券）時按返回＝取消全部勾選；搜尋框有字時先清掉搜尋；詳情頁的編輯表單開著時先收起表單（不存）；匯入還沒存的時候，第一次右滑只提醒，5 秒內再右滑才放棄；選了種類、商家頁籤、上面那排篩選（30 天內到期、已分享…）、已結束底下的「已使用」，返回一層一層退回「可用」「全部」；放大圖放大中先縮回。
列表捲到下面時，返回先捲回最上面；出示模式（兩張以上）滑到後面，返回先回第 1 張；詳情頁用上方「︿ 2 / 82 ﹀」切到別張之後，返回先回進來時的那一張。什麼都沒開、也是預設檢視時，返回什麼都不發生，App 不會被關掉（要離開用手機的首頁手勢）；連滑好幾下也一樣。只有打開 App 後、第一次點畫面之前右滑，會離開（Chrome 的規定）。右滑被關掉的話，重開 App 看「設定 → 版本」那一行返回鍵的記錄。上面那條「目前離線…」不再顯示，只有離線按了「已使用」、還沒同步時才會出現「有 N 筆標記等連線後同步」。
設定頁（v80）：上面四格（親友連結、分享紀錄、餘額型、檢查重複）看一行狀態，點進去才有細節；下面四列是匯入、圖檔、通知、連線與裝置；最下面是更新卡（版本、上次部署、「檢查更新」「強制更新」，詳細資訊摺起來）。從設定點進去的頁，返回會回到設定。更新程式的做法見上面「之後怎麼更新」。

精簡列表（v87）：列表預設用精簡版——不顯示序號和「1」「1張」「大」這類份量（金額、2 以上的數量、餘額、已分享照舊），卡片矮一半，一個畫面看得到五張以上；詳情頁、出示模式不變。想要原本的樣子：設定 →「列表」→「完整」，記在這台裝置。「已結束 → 已使用」照用掉的時間排，最近用的在最上面。已使用的票根最上面寫「已使用 10/6」，大字是用掉的時間（14:32:05，到秒；v88 起才有記，之前用掉的寫「—」）。時間記的是按下「已使用」的那一刻，分享連結、親友連結標的也記；改回未使用就清掉。
主畫面（v83，v95 改）：最下面一條是搜尋（右邊是可用張數）、紫色 ＋（拍照或匯入／手動輸入一張，選單往上長）、設定齒輪，拇指按得到；打字時鍵盤跳出來，這條會跟著往上抬；多選時換成「取消／出示／分享」那一條。上面一列是日期/商家切換和篩選（可用、30 天內到期、已分享、餘額型、已結束、全部）。點「已結束」時，第二排只剩「已結束 ✕｜全部｜已使用」，先看已使用的；已過期的在「全部」裡；按 ✕ 回「可用」。依商家看：商家頁籤橫向排開，按一家就只看那一家（變成一顆「(logo) 店名 N ✕」，種類接在後面，按 ✕ 回到全部）；選了商家之後，「＋ 商家」在選到的商家正下面（v86），種類接在它右邊。商家太多時，連點兩下「全部」（或選了之後按「＋ 商家」）往下展開，一家一家點可以選好幾家，按「完成」收回去，只剩選到的那幾顆。最下面的 ＋ 按一下出小選單：拍照或匯入、手動輸入一張。選取：長按票券（或點票券最左邊的色帶）就進多選，底下升起「取消／出示這 N 張／分享」，沒在多選時底下什麼都沒有。

店家小圖示（v81）：票券列表、商家頁籤、詳情頁標題、出示模式的商家名稱前面有一顆圓形小圖。麥當勞、7-ELEVEN、全家、肯德基、摩斯漢堡用 `web/brands/` 裡的 logo，星巴克用內建的簡化綠圈，其他店用「第一個字＋品牌色」；圖載不到會自動退回字章。v82 起星巴克、全聯、家樂福（和萬家福/樂家康）、SOGO、清心福全、萊爾富、Mister Donut 也用店家的圖（`.png`，已經置中、白底、正方形，`p` 是 100%）。要加店或換圖：改 `index.html` 的 `BRAND_MARK`，檔案放 `web/brands/`，檔名加進 `sw.js` 的 `BRAND_FILES` 。logo 的商標屬各家所有，僅供自用；不想用的話把 `web/brands` 資料夾刪掉，會自動退回「第一個字＋品牌色」。
讀不到票券清單時 App 會自己再試（4、12、30、60 秒後），從背景回來超過 1 分鐘也會自動重新讀；設定 → 版本會寫最近一次讀到、最近一次失敗的時間和原因。

**朋友手上快到期的**　分享出去的票不會列在「30 天內到期」，所以那一格最上面會多一條提示，例如
「另外朋友手上有 3 張 30 天內到期、還沒用：小明 2 張、阿華 1 張，最快 4 天後到期」，
按「查看」跳到「已分享」（也可以「今天不再顯示」）。其他格不放這條，打開 App 不會一堆提示。
對方連結一次都沒打開過的，卡片上會標「對方還沒打開」。點進那張票券：

- 「提醒小明」：用手機的分享選單傳一則提醒給他，同一個連結裡他還沒用的都會列出來，附上原本的連結
- 「收回這張」（按兩下）：只收回這一張，畫面停在這張可以直接出示；同一個連結的其他張他照樣能用，
  收到一張不剩整個連結才失效。他剛好已經用掉的話會告訴你，不會收回
- 「收回整條連結」（按兩下，v86）：同一個連結裡還有兩張以上沒用掉時才出現，一次把整條收回來，對方已經用掉的不變

設定 →「分享」裡分享出去的連結，每一筆也會寫「還沒用 N 張，最快幾號到期」，旁邊有「提醒」。
自己在那裡按「開啟」看分享頁不會算進開啟次數。

**一次收回好幾張**　按「已分享」，點票券左邊的圈勾幾張，底下的「分享」會換成「收回 N 張」。按一次只提示會動到
幾張、同連結沒勾的還有幾張他還能用，再按一次才真的收回；整個連結的票都勾了，那個連結就打不開。
他剛好已經用掉的不會收回，會告訴你有幾張，其他照收。

**同時操作也不會寫錯**　所有寫進試算表的動作（新增、改狀態、刪除、分享、收回、朋友按用掉或還給你、
自動匯入寫入）都會排隊，一次只做一個，所以連續刪好幾張、或朋友按的同時你也在改，都不會刪錯或蓋到別張。
自動匯入只有寫進表的那一下才排隊，辨識的幾分鐘不會卡住 App。萬一排了 20 秒還輪不到，
會顯示「後端正忙，請稍後再試一次」，資料不會動到。

## 離線也能出示

App 會把票券清單存在手機上，打開時先顯示存著的，再到後端更新，所以打開就有畫面。
連上 Wi-Fi 時會把還能用的票券截圖先存到手機（用行動網路時不預先下載，打開過的那張才會存），
在地下室、賣場收訊不好時一樣能出示條碼。

離線時畫面上方會出現黃色提示，寫著顯示的是幾點的資料。這時按「已使用」會先記在手機上，
恢復連線後自動補送，Discord 通知也會在那時才發。

## 自動匯入（手機丟了就不用管）

適合不想守著畫面等辨識的情況，iPhone 也能用。

1. 在雲端硬碟開一個資料夾，例如「票券收件匣」，把網址 `.../folders/` 後面那一串填進指令碼屬性 `SOURCE_FOLDER_ID`。
2. 在編輯器選 `startAutoImport` 按一次執行。之後每 15 分鐘會自己掃一次那個資料夾。
3. 手機上看到票券畫面就截圖，然後從相簿分享到「雲端硬碟」App，存進那個資料夾。關掉手機去做別的事。
4. 匯好之後 Discord 會通知「自動匯入了 N 張票券」，辨識沒把握的會標成「待確認」，
   商家或券名重複的會標「可能重複」，你有空再開 App 檢查。

處理過的截圖會自動搬離上傳區：成功的搬到 App 的「票券截圖」資料夾，序號重複的放進上傳區裡的「重複」子資料夾，辨識失敗的放進「辨識失敗」子資料夾（拖回上傳區就會重試）。所以上傳區永遠只剩還沒處理的，掃起來很快。Discord 會條列每一張新增的券、到期日和要注意的地方。

等不及 15 分鐘的話，到 App「設定 → 匯入與整理 → 雲端硬碟上傳區」按一下就會馬上辨識（一次跑約 70 秒，沒跑完再按一次）。
按完那一行會寫匯入了幾張，還有 Discord 通知送出了沒（例如「新增 2 張。Discord 通知已送出（03:33:43 收到）」）。

不想再自動跑就執行 `stopAutoImport`。兩輪不會疊在一起跑，Gemini 額度滿了會記住進度，下一輪接著做。

## 把雲端硬碟裡既有的票券圖一次匯進來

如果你本來就有一個資料夾堆著票券截圖，不用一張張從手機傳。

1. 開那個資料夾，網址長這樣 `https://drive.google.com/drive/folders/【一串ID】`，把那串 ID 複製起來。
2. Apps Script →「專案設定 → 指令碼屬性」→ 新增 `SOURCE_FOLDER_ID`，值貼上去。
3. 函式選單選 `importDriveFolder`，按執行，然後看「執行記錄」。

Apps Script 單次最多跑六分鐘，所以它做到大約四分半就會停下來並記住進度，記錄會告訴你還沒做完。
再按一次執行就接著跑，跑到記錄出現「整個資料夾都做完了」為止。碰到 Gemini 額度上限也一樣——
等幾分鐘再執行一次就好，不會重頭來。

已經匯入過的檔案、內容重複的票券都會自動跳過，所以重跑永遠是安全的。想從頭掃一次就執行 `resetDriveImport`。

匯進來的票券是**連結**到你原本那張圖，不是複製一份，所以不佔額外空間；之後在 App 裡刪掉這張票券
也不會動到你的原檔。辨識沒把握的會在備註填「待確認」，在 App 的搜尋框打「待確認」就能把它們挑出來檢查。

## 讓分享網址變短

v98 起不用自己設：App 第一次打開時會檢查你的網站有沒有接上後端（抓 `https://你的網站/s/test`），
接上了就自動告訴後端用這個網站當分享連結的開頭（`SHORT_BASE`）。之後每天檢查一次，
分享連結打不開時列表上方會提醒、右上角鈴鐺變紅點，照「設定 → 右上角鈴鐺 → 分享短網址」那格做就好。

短網址長這樣：`https://你的網站/s/xxxxxxxxxxxx`（約 44 字）。沒有短網址時分享連結是 Apps Script 的網址，大概 96 個字，一樣能用。

想更短就接自己的網域，例如 `https://t.你的網域/s/xxxx`，在 Cloudflare Pages 的「自訂網域」設定，再到指令碼屬性把 `SHORT_BASE` 改成新網域。
做法是靠 `web/_worker.js`（Cloudflare Pages 的進階模式）：

* `/s/<token>` 由它在伺服器端去抓 `…/exec?s=<token>&raw=1`，那個網址回的是 JSON 包著的純 HTML
  （直接抓 `/exec` 會拿到 Apps Script 自己的沙箱外框，畫面會是一片空白），再把 HTML 送給對方。
* 分享頁按「我用掉了」時打的 `/api` 也由它代轉。

對方的瀏覽器完全不會連到 `script.google.com`，所以不管他有沒有登入 Google、登入幾個帳號，
都不會看到「Sorry, unable to open the file at this time」那張 Drive 錯誤頁 —— 那是 Google 在
多重登入時解析 `/macros/s/...` 失敗的畫面，跟權限和程式無關。

後端網址記在 `web/_worker.js` 最上面的 `EXEC`（網站產生器填的），或 Cloudflare 的 `EXEC_URL`（兩個都有的話用 EXEC_URL；EXEC_URL 格式不對就用檔案裡的）。
換部署（重建部署作業）時，用網站產生器重新下載一次網站再「建立部署」。部署新版本不用改，網址不會變。不要放 `_redirects`，Cloudflare Pages 不會把 `:token` 代換進查詢字串。

## 通知（有人用掉你分享的券時）

別人透過分享連結按「我用掉了」，你會收到：

```
小美的姊姊 於 09/21 14:32:05 使用了「星巴克 買一送一飲料券」
```

產生分享連結時也會發一則紀錄：給了誰、哪幾張、連結、什麼時候失效，
最後一欄還會寫現在總共有幾個連結在外面、共幾張、用掉幾張。
有人用掉或復原時，那一則也會附上該連結的網址和它還剩幾張沒用。
不想收這種就把 `Code.gs` 裡的 `NOTIFY_SHARE` 改成 `false`。

Discord 那邊底下還會附一張小卡，寫序號、到期日、當初分享給誰。對方 30 分鐘內按了復原也會再通知一次。
你自己在 App 裡標記已使用、或把它改回未使用，也會通知（小卡上會寫「自己在 App 裡標記」），
當成一份使用紀錄。不想收這種的話，把 `Code.gs` 裡的 `NOTIFY_SELF` 改成 `false`。

App 裡拍照或匯入存完也會發一則「票券匯入（App）」（寫法見上面「用法」），不想收就把 `NOTIFY_APP_IMPORT` 改成 `false`。

Discord 和 LINE 兩個管道都寫好了，設了哪個就發哪個，兩個都設就兩邊都發。通知失敗（網址失效、額度用完）
不會影響票券本身，只是那則沒送到。每一則有沒有送到、Discord 幾點收到、沒送到的原因，
都可以在 App「設定 → 右上角鈴鐺 → 最近送出的通知」看到（記最近 15 則）。

Discord 通知送不到時會自動補送（v55 起）：先等幾秒重試一次；還是不行就排進「補送」，之後自動再送。
補送的時機是每 15 分鐘的自動匯入、每天早上的到期提醒、下一則通知送到的時候，也可以在「最近送出的通知」按「現在補送」。
補送的那則最上面會寫「（補送｜原本 09/26 03:33 要送，晚了 45 分鐘）」。最多排 10 則，超過 3 天還送不到就放棄；
Discord 說格式不對（400）的不補送，測試通知和預覽提醒也不補送。

通知一律先經你自己的 Cloudflare 網站轉送到 Discord（`_worker.js` 的 `/relay/discord`，v58 起）。因為 Apps Script 用的是很多人共用的 Google IP，Discord 會不定時整批擋掉（「最近送出的通知」會寫「429 error code: 1015」），從自己的網站送就不受影響。紀錄上會標「經 Cloudflare」。
轉送的網址用 `SHORT_BASE` 的網域，所以要先設好短網址（沒設就直接從 Google 送，被擋時只能等補送）。每一則轉送前，網站都會回頭跟後端確認「這一則真的是你剛剛要送的」，別人沒辦法拿它來亂發。轉送這條路有問題（例如網站還沒更新）時會改直接送，紀錄上會寫原因。想改回「先直接送、被擋才轉送」：指令碼屬性加 `DISCORD_VIA`，值填 `direct`。

設定好之後，函式選 `testNotify` 按執行，每個管道都會收到一則測試訊息。
改通知的指令碼屬性**不用重新部署**，改完就生效。

到期前 10 天開始，每天早上 9 點多 Discord 會列出還沒用掉的票券，直到用掉或過期為止：

```

今天到期（1 張）
• 星巴克 中杯拿鐵（1 杯）　09/25
5 天後到期（6 張）
• 麥當勞 大薯（1 份）　09/30
…
朋友手上還沒用（2 張）
• 阿華：清心福全 烏龍綠茶　明天到期（09/26）　連結開過 3 次
• 小明：星巴克 中杯拿鐵　3 天後到期（09/28）　還沒打開過連結
```

分享出去的另外列在「朋友手上還沒用」，看連結開過沒就知道該不該提醒他；
點「看朋友手上的」會直接打開 App 的「已分享」。10 天內都沒有要到期的就不發。排程在執行 `setup` 的時候就裝好了，不用手動設定；要先設好 Discord（見下面「Discord」）才收得到。
想先看看：App「設定 → 右上角鈴鐺 → 預覽到期提醒」。會寫「10 天內沒有要到期的票券」、「已送到 Discord（N 張）」，
或「有要提醒的 N 張，但 Discord 沒送到：原因」。
每天早上的提醒有沒有跑，看「設定 → 右上角鈴鐺 → 最近送出的通知」：有發會列那一則，沒東西發也會記一筆「今天不用發」。
提醒的排程如果不見了，那裡會出現「每天早上的到期提醒排程不見了」，按一下就裝回去。
不想收：在編輯器執行 `stopReminder`；要恢復就執行 `startReminder`。
想改提醒的時間或天數：改 `Code.gs` 裡的 `REMIND_HOUR`、`REMIND_WITHIN`，再重新部署一次（見「改了程式之後」）。

### 通知很慢才到手機，怎麼查

先到 App「設定 → 右上角鈴鐺 → 最近送出的通知」看那一則：寫「✓ Discord 幾點收到」就是票券這邊已經送到了，
問題在 Discord 推播到手機那一段（看下面兩點）；寫「✗ 沒送到」會附原因，例如 webhook 被刪掉就要重建一個。

票券這一邊送到 Discord 大約 1 秒（實測：找票 0.12 秒、寫入 0.34 秒、送 Discord 0.49 秒，
Discord 伺服器 0.23 秒內就收到）。所以手機晚好幾分鐘才響，問題幾乎都在 Discord 推播到手機那一段：

1. **電腦上開著 Discord（App 或網頁版）**：Discord 會先把通知給正在使用的電腦，
   要等電腦閒置一段時間才推到手機。這個等待時間在 Discord 的「使用者設定 → 通知」裡
   （英文介面叫 Push Notification Inactive Timeout），最短 1 分鐘。不需要的話把電腦上的 Discord 關掉。
2. **手機的省電設定把 Discord 凍結了**（OPPO、小米、三星等 Android 都有類似設定）：到手機「設定 → 電池」把 Discord 設成不限制／不最佳化，
   「應用程式管理 → Discord」打開自動啟動和允許背景執行。各家手機的選項名稱略有不同。

改完之後，在 App「設定 → 右上角鈴鐺 → 傳一則測試通知」按一下，訊息裡寫著後端送出的時間，
跟手機跳出來的時間比一比就知道好了沒。每則「已使用」通知底下也會小字寫「從按下到送出 X 秒」。

更細的數字：在編輯器執行 `diagnoseLatency`，會分段量後端每一步並送一則測試訊息；
Apps Script 的「執行項目」看得到每個請求有沒有跑、跑多久；但 App 按的動作（網頁請求）Google 不留記錄內容，
只有排程（自動匯入、每日提醒）和在編輯器執行的才看得到記錄，所以通知結果改成記在 App 的「最近送出的通知」。

### 「無效期」的券被讀成到期日

有些券寫「兌換期間至：2026.09.24 ～ 無效期」，前面那個其實是開始日，後面才是說沒有到期日。
提示詞已經講明這種寫法，後端也會再檢查一次 rawText，看到「無效期／無期限／長期有效」就把到期日清空，
列表上會顯示「不限　無到期日」，依日期看時也會自成一組「無到期日」，排在「接下來」後面。

### 序號被存成 7.3E+15 怎麼辦

十六位數的序號如果被試算表當成數字，尾數會被四捨五入，兩張不同的券就會長得一樣。
新版寫入前會先把該列設成文字格式，辨識時也會擋掉科學記號並回頭從 rawText 撈完整數字。
已經壞掉的舊資料，在編輯器選 `fixSciCodes` 按執行修一次，紀錄會寫出修好幾張、清空幾張。

### Discord（推薦，沒有額度限制）

1. Discord 左邊「＋」建立一個自己的伺服器（選「自己建立 → 僅供我和我的朋友使用」），或用你已經有的。
2. 建一個文字頻道，例如 `#票券`。
3. 頻道名稱旁的齒輪「編輯頻道」→「整合」→「Webhook」→「新 Webhook」→ 點開它 →「複製 Webhook 網址」。
   名字和頭像可以順便改成「票券」，不改也行，程式會自己帶名字。
4. Apps Script →「專案設定 → 指令碼屬性」新增 `DISCORD_WEBHOOK`，值貼那串網址。
5. 執行 `testNotify`。

**一定要檢查手機通知設定**：webhook 發的訊息不會 @ 你，如果伺服器的通知預設是「只有 @提及」，
手機就不會跳。對那個頻道（或整個伺服器）長按 →「通知設定」→ 改成「所有訊息」。

webhook 網址等於這個頻道的發文權限，拿到的人都能往裡面貼訊息，所以只放在指令碼屬性裡、不要貼給別人。
萬一外流了，回到同一個地方把那個 webhook 刪掉再建一個新的就好。

### LINE（選用）

LINE Notify 已經在 2025 年 3 月停止服務，所以要用 LINE 官方帳號的 Messaging API。
免費方案每月 200 則主動推播，個人用很夠。

1. 開 <https://manager.line.biz> 用你的 LINE 登入 → 建立 LINE 官方帳號（名稱隨便取）。
2. 進到這個官方帳號 → 右上「設定」→ 左邊「Messaging API」→「啟用 Messaging API」→ 建立一個服務提供者。
3. 開 <https://developers.line.biz/console/> → 點剛剛的服務提供者 → 點那個頻道：
   - 「Basic settings」分頁最下面的 **Your user ID**（U 開頭）複製起來。
   - 「Messaging API」分頁最下面的 **Channel access token (long-lived)** 按 Issue，複製起來。
   - 同一頁上面的 QR code 用手機掃，把官方帳號**加為好友**（沒加好友收不到）。
4. 指令碼屬性新增 `LINE_TOKEN` 和 `LINE_USER_ID`。
5. 執行 `testNotify`。

建議在官方帳號的「回應設定」把歡迎訊息和自動回應關掉，免得它自己亂回話。

## 辨識引擎怎麼選

| | Gemini | Claude | Vision API + 規則 |
|---|---|---|---|
| 費用 | 有免費額度，個人量用不完 | 付費，約每張截圖 NT$0.1 | 每月前 1000 張免費 |
| 中文票券辨識 | 夠用 | 夠用 | 只取字，不理解 |
| 版面雜亂時判斷到期日 | 偶爾會抓到購買日 | 比較穩 | 靠關鍵字硬猜，常錯 |
| 設定 | App「設定 → 右上角鈴鐺 → 辨識金鑰」選 Gemini（存成 `GEMINI_KEY`） | 同一格選 Claude（存成 `ANTHROPIC_KEY`） | 指令碼屬性 `VISION_KEY` |

實務建議：先用 Gemini，免費而且多數票券截圖都讀得出來。真的遇到一批老是抓錯的（飯店住宿券、
旅行社憑證這種版面複雜的），在「辨識金鑰」那格選 Claude 貼上金鑰（兩支都有的話預設用 Claude；
想指定就在指令碼屬性加 `ENGINE`，值 `claude` 或 `gemini`），再匯入一次比較看看。程式裡兩個都實作好了，換引擎不用動程式碼。

Claude 的金鑰是 Anthropic API 的金鑰，跟 Claude 網頁版或桌面版的訂閱是分開的兩件事 ——
訂閱不會給你 API 額度，API 也不會扣訂閱的用量。

## 之後可能想改的地方

**模型換掉了**　如果匯入時跳「說沒有這個模型」，去官方文件看現在的型號：
Gemini 在 <https://ai.google.dev/gemini-api/docs/models>（改 `Code.gs` 的 `var MODEL`），
Claude 在 <https://platform.claude.com/docs>（改 `var CLAUDE_MODEL`），然後重新部署。

**改了程式之後**　Apps Script 每次改都要「部署 →管理部署作業 → 編輯（鉛筆）→ 版本選『新版本』→ 部署」，
網址不會變。前端改了就重新上傳一次，並把 `sw.js` 裡的 `VERSION` 加一，手機才會抓到新版。
自己改了程式的話，下次從「有新版本」更新時會蓋掉你改的地方，記得先留一份。

## 卡住的時候

| 症狀 | 多半是 |
|---|---|
| 測試連線說「後端回傳的不是 JSON」 | 部署的「誰可以存取」不是「所有人」，或網址少了 `/exec` |
| 測試連線說「存取碼不對」 | OWNER_KEY 貼錯，或後端換了新的指令碼屬性 |
| 匯入時說「存不進雲端硬碟」 | `FOLDER_ID` 那個資料夾被刪了，把屬性清掉再跑一次 `setup()` |
| 匯入前說「還沒設定辨識金鑰」 | 到 App「設定 → 右上角鈴鐺 → 辨識金鑰」貼上 |
| 存金鑰時說「這支金鑰不能用」 | 回 aistudio.google.com/apikey 重新複製一次，前後不要多複製到空白 |
| 列表上方說「分享出去的連結現在打不開」 | 網站還不知道後端網址：「設定 → 右上角鈴鐺 → 分享短網址」按「下載填好的網站」，到 Cloudflare 右上角「建立部署」拖進去 |
| 朋友打開分享連結看到 Google 的錯誤頁 | 還在用 Google 的長網址：看「設定 → 右上角鈴鐺 → 分享短網址」那格 |
| 分享連結打開是空白或 404 | 部署後沒有更新網址；或在指令碼屬性加一個 `WEBAPP_URL`，值就是你的 `/exec` 網址 |
| 辨識好的一直沒出現 | 列表上方寫「辨識中」就是還在跑（App 關掉也會繼續，Gemini 額度滿了會等 15 分鐘）；「設定 → 匯入與整理」看得到進度 |
| iPhone 上沒有「加入主畫面」 | 用的不是 Safari |

## 安全

- `OWNER_KEY`（存取碼）和 App「設定 → 右上角鈴鐺 → 換到另一台裝置」的 QR 碼／設定連結，等於你所有票券的鑰匙，只給自己的裝置，不要傳給別人。
- 想給朋友看看長什麼樣子，直接給他你的網站網址就好：他的手機沒有存取碼，會自動進「示範模式」，看到的是範例票券。
- 覺得存取碼外流了：把指令碼屬性的 `OWNER_KEY` 改成一串新的，手機重新填一次就好。
